# Размещение релиза 0.3.3

В архиве нет токенов, паролей и пользовательских сессий. Аккаунты подключаются после установки: **/start → Аккаунты → Добавить аккаунт · QR**. Несколько аккаунтов работают одновременно; настройки и одна активная сделка хранятся отдельно для каждого.

## Какой бесплатный хостинг выбрать

Для постоянного поиска с HTTPS-страницей входа подходит по заявленным условиям **Northflank Sandbox**: есть бесплатные сервисы и база, без сна. Проверь доступность бесплатного плана в своей панели и итоговую оценку стоимости до создания ресурсов. Этот релиз ещё не развёрнут в твоём аккаунте хостинга. [Тариф Northflank](https://northflank.com/pricing).

**FadeHost тоже поддерживается**, но у бесплатного приложения с публичным веб-адресом есть сон при простое. Веб-адрес нужен для QR/2FA Mini App; когда приложение спит, поиск не работает. Поэтому бесплатный FadeHost с этой формой входа не обещает непрерывный поиск. Ограничение нельзя исправить внутри Python-скрипта. [Правила бесплатного плана](https://fadehost.com/docs/app-free-plan/).

## Общие настройки

Добавь в Environment/Secrets хостинга:

| Имя | Значение |
| --- | --- |
| `BOT_TOKEN` | Токен своего управляющего бота из BotFather |
| `ADMIN_USER_ID` | Числовой ID владельца управляющего бота; это может быть другой аккаунт, чем подключаемые для поиска |
| `TELEGRAM_API_ID` | API ID приложения из my.telegram.org |
| `TELEGRAM_API_HASH` | API hash того же приложения |
| `BOT_TRANSPORT` | `polling` |
| `MONITOR_SOURCE` | `userbot` |
| `PUBLIC_BASE_URL` | Полный выданный хостингом HTTPS-адрес, без `/connect` |
| `LIVE_TRADING_ENABLED` | `true`, если нужна автопокупка; она всё равно включается владельцем отдельно для каждого аккаунта |
| `MAX_ACCOUNTS` | `3` по умолчанию; можно изменить после проверки памяти и нагрузки |
| `REFRESH_SECONDS` | `1`; целевой интервал начала проходов, ограничения Telegram имеют приоритет |
| `ACTION_INTERVAL` | `0.2`; минимальная пауза между нажатиями в секундах |

На публичном хостинге убери `PUBLIC_BASE_URL_FILE`, если переносишь настройки с ПК: вместо временного туннеля используется стабильный `PUBLIC_BASE_URL`.

Один процесс приложения обслуживает все аккаунты. **Workers/replicas = 1**, без `--reload` и автоскейлинга в несколько реплик. При обновлении сначала останови старый экземпляр, затем запускай новый: перекрывающийся rolling deploy будет ждать освобождения блокировки базы. При переносе того же управляющего бота останови его старый запуск на ПК: два процесса не должны одновременно читать обновления одного Bot API токена. Если раньше был webhook, выполни локально `python -m sniper polling` с настройками этого бота перед переходом на polling.

## Вариант A — Northflank

1. Распакуй архив, помести содержимое в приватный Git-репозиторий. `.env`, `hosting-secrets.env`, базы, `/data` и сессии не добавляй. Создай проект на Sandbox.
2. В проекте создай PostgreSQL addon в пределах бесплатной квоты. Возьми строку подключения из Connection details и передай её сервису как `DATABASE_URL`. Сохрани TLS-параметры провайдера; если нужен собственный CA, установи его по инструкции базы, не отключай проверку сертификата. [PostgreSQL на Northflank](https://northflank.com/docs/v1/application/databases-and-persistence/deploy-databases-on-northflank/deploy-postgresql-on-northflank), [доступ и TLS](https://northflank.com/docs/v1/application/databases-and-persistence/access-a-database).
3. На своём ПК с установленными зависимостями запусти `python scripts/make_host_secrets.py`. Он создаст приватный `hosting-secrets.env` без печати ключей. Перенеси `APP_KEY` и `WEBHOOK_SECRET` в Secrets хостинга. Для переноса существующей базы нужны **её старые ключи**, новые генерировать нельзя.
4. Создай Combined service из репозитория, сборка **Dockerfile**, путь `Dockerfile`, контекст — корень проекта. Добавь общие настройки выше, `DATABASE_URL`, `APP_KEY`, `WEBHOOK_SECRET`, `PORT=8000`. Запуск уже указан в Dockerfile: `python main.py`. [Сборка сервиса](https://northflank.com/docs/v1/application/getting-started/build-and-deploy-your-code).
5. Опубликуй HTTP-порт `8000`. Скопируй его HTTPS-адрес в `PUBLIC_BASE_URL` и перезапусти сервис. Health check — `/healthz`; при смене процесса блокировка базы может освобождаться до 125 секунд, поэтому стартовой проверке дай запас времени. [Публичный порт](https://northflank.com/docs/v1/application/network/configure-ports).
6. Открой бота, отправь `/start`, затем подключи аккаунты по инструкции ниже. Не используй SQLite внутри непостоянного контейнера: данные релиза находятся в PostgreSQL.

## Вариант B — FadeHost

1. Создай бесплатное приложение/Telegram-бот. Выбери Python **3.13** (программа требует 3.12+). Можно загрузить архив через Files → Extract; `main.py`, `requirements.txt`, `sniper` и `migrations` должны оказаться в корне запуска. [Загрузка файлов](https://fadehost.com/docs/app-files/).
2. Install/build: `pip install -r requirements.txt`. Start: **`python main.py`**. Хостинг также умеет определить эти файлы автоматически. [Python и команды запуска](https://fadehost.com/docs/app-hosting/).
3. Добавь общие настройки из таблицы и `DATA_DIR=/data/cryptobot-state`. `DATABASE_URL`, `APP_KEY`, `WEBHOOK_SECRET`, `USER_SESSION_ENCRYPTED` для **новой установки** можно не задавать: `main.py` создаст SQLite и ключи в постоянном каталоге. Не задавай эти переменные пустыми. Порт берётся из `PORT`, который предоставляет хостинг.
4. Включи веб-адрес, укажи его как `PUBLIC_BASE_URL`, перезапусти. В конфигурации сна выбери подходящий доступный интервал; сам сон бесплатного веб-приложения остаётся ограничением хостинга.
5. Дождись успешного `/healthz`, подключи аккаунты через бота. Сохраняй приватную резервную копию **всего** `/data/cryptobot-state`, включая `keys.json`: без ключа сессии и настройки не расшифровать.

Бесплатный FadeHost указывает 256 MB RAM, 3 GB постоянного диска и 1 GB суммарного трафика в сутки. При превышении квоты возможна остановка. Нагрузка нескольких реальных аккаунтов на этом тарифе не измерялась; число `MAX_ACCOUNTS=3` — лимит программы, а не гарантия ресурсов. [Квоты](https://fadehost.com/docs/app-free-plan/).

## Вход и работа в Telegram

1. Управляющий бот: `/start` → **Аккаунты** → **Добавить аккаунт · QR**. Кнопка доступна владельцу и одобренным пользователям; каждый подключает свои аккаунты.
2. Открой Mini App на компьютере и нажми «Показать QR-код».
3. На телефоне в **нужном аккаунте**: Telegram → Настройки → Устройства → Подключить устройство. Отсканируй QR и подтверди вход. Сканер требуется на другом устройстве, чем экран с QR.
4. Если у аккаунта есть 2FA, форма запросит облачный пароль. Вводи его **в форму Mini App**, не сообщением боту. Пароль не сохраняется. QR обновляется автоматически; попытка входа действует пять минут.
5. После успеха закрой Mini App, открой **Аккаунты**, выбери подключённый аккаунт. Настрой режим и курс, запусти поиск. Для автопокупки потребуется отдельное подтверждение.
6. Повтори для других аккаунтов. Выбор аккаунта меняет панель, но остальные продолжают работать. Уведомления содержат имя аккаунта, кнопки привязаны к нему. `/stopall` останавливает новые поиски на всех аккаунтах; открытые сделки сохраняются.

После рестарта автопокупка выключается для всех аккаунтов и требует нового подтверждения. Пароли 2FA не восстанавливаются: незавершённый вход нужно начать заново. Подключённые сессии и настройки сохраняются в зашифрованной базе.

Если Mini App показывает «Открой вход кнопкой…», открой его заново через бота: подпись доступа ограничена по времени. Если кнопки добавления нет, проверь `PUBLIC_BASE_URL`. При отзыве пользовательской сессии останови её поиск, проверь открытые сделки, удали аккаунт из помощника и подключи снова. Удаление из помощника не отзывает авторизацию в Telegram; для этого используй официальный раздел «Устройства».

## Что проверено в этом релизе

Автоматические тесты проверяют изоляцию аккаунтов, QR с/без 2FA, неверный пароль, повторный вход, владельца Mini App, истечение подписи, привязку кнопок, сохранение и перезапуск. Подробный отчёт — `VALIDATION.md`. Выдача настоящего QR проверена на локальном HTTPS-развёртывании (LIVE_ACCESS_CHECK.md); завершение реального входа с 2FA и работа на выбранном хостинге проверяются после развёртывания владельцем. Реальное создание/отмена сделок не объявляются проверенными этим релизом.
