# CryptoBot Assistant 0.3.3 — восстановление поиска

**Исправление 0.3.3:** временная смена экрана, задержка ответа или исчезнувшая карточка вызывают восстановление рынка вместо немедленного выключения поиска. Повторный проход заново проверяет цену и сумму. После отправки команды создания неизвестный исход остаётся заблокированным.

**Доступ по заявкам:** пользователь отправляет `/start`, владелец одобряет его ID, после чего пользователь подключает собственные аккаунты. Кнопка «Доступ пользователей» и `/users` управляют разрешениями. Подробности: [USER_ACCESS.md](USER_ACCESS.md).

Python 3.12+, Telethon, управляющий Telegram-бот, QR/2FA Mini App, SQLite/PostgreSQL и Docker.

**Релиз для хостинга:** начни с [HOSTING.md](HOSTING.md). Там есть установка на FadeHost и Northflank, переменные окружения и вход через кнопку в боте. [RELEASE_NOTES.md](RELEASE_NOTES.md) описывает изменения и границы проверки версии 0.3.3.

**Исправление 0.2.1:** сообщения продавцов по сделкам не подменяют экран объявлений и не создают ложную отметку активной сделки. Текст продавца не считается подтверждением отмены, оплаты или завершения.

**Живая проверка 16.11.2026:** на подключённом аккаунте открыты USDT/RUB/СБП, обновлена страница «1», прочитаны объявления и условия. Проверены оба пути до подтверждения: фиксированная сумма и выбор «Макс.». Реальное создание и отмена сделки не выполнялись. Подробности — `LIVE_VERIFICATION.md`. До отправки команды создания программа делает до трёх попыток восстановить навигацию. Если это не удалось или исход отправки неизвестен, новые операции блокируются с диагностикой.

## Что делает

- Несколько пользовательских аккаунтов работают параллельно; у каждого отдельные курсы, история, пауза и активная сделка. Покупка USDT за RUB через СБП.
- `/p2p` → «Купить» → USDT → СБП → первая страница. Повторное нажатие «1» обновляет её.
- **Уведомления:** диапазон курса «от/до» задаётся в управляющем боте. При совпадении приходит карточка и текст условий.
- **Авто:** отдельный максимальный курс. Объявление с диапазоном проходит «Купить USDT» → «Макс.»; фиксированная сумма сразу открывает подтверждение. Перед созданием повторно проверяются курс, сумма и включение режима владельцем.
- Максимум определяется текущей кнопкой «Макс.» либо точным объёмом кнопки покупки для фиксированной суммы. Дополнительного ограничения суммы, дневного лимита и фильтра рейтинга нет. Одновременно допускается **одна** активная/неопределённая операция **на аккаунт**.
- «Многозадачность» и варианты написания вызывают предупреждение и отправку условий; это не основание пропускать объявление.
- При создании заявки поиск приостанавливается. Для распознанной сделки доступна отмена с подтверждением в управляющем боте. Автоматической отправки денег, отметки «Оплачено» или выпуска криптовалюты нет.
- После подтверждённой отмены/завершения поиск возобновляется, объявление исключается из повторного подбора. Неопределённый исход никогда не повторяется автоматически.
- В меню два режима: уведомления и автопокупка. Старые кнопки симуляции не включают её.

## Управление в боте

`/start` выводит новое главное меню внизу чата. Повторные команды в течение пяти секунд используют то же меню. Переходы между разделами обновляют последнее меню без новых сообщений. Устаревшие кнопки показывают подсказку отправить `/start`.

- **Главная:** запуск/пауза, переключение режима, курс, сделка, статистика и история.
- **Аккаунты:** добавить по QR с 2FA, выбрать аккаунт для управления, удалить остановленный аккаунт без активной сделки. Переключение панели не останавливает остальные аккаунты. `/stopall` останавливает поиск на всех.
- QR и 2FA открываются в Mini App по HTTPS. Сервер проверяет подпись Telegram и разрешение пользователя; владелец `ADMIN_USER_ID` одобряет заявки. Пароль не отправляется сообщением и не сохраняется. Сессии сохраняются зашифрованными в базе каждого пользователя.
- При первом выборе автопокупки сразу открывается ввод её максимального курса. Курс уведомлений хранится отдельно. После сохранения появляется «Запустить поиск»; ввод курса сам по себе не запускает сделки.
- **Настроить курс:** отдельный порог автопокупки либо диапазон уведомлений. Диапазон можно ввести целиком двумя числами через пробел.
- **Сделка:** текущий статус, проверка в CryptoBot и доступная отмена с подтверждением. После запроса отмены повторная кнопка скрывается.
- Кнопки старого экрана не повторяют операции. Нажатие уже выбранного режима не останавливает работающий поиск.
- Короткая карточка и условия приходят одним уведомлением. Изменение только объёма не создаёт повторное уведомление; изменения курса или условий сообщаются.

Длинные условия разбиваются только из-за ограничения длины сообщений Telegram. События по объявлениям и сделкам остаются отдельными уведомлениями.

## Условия запуска

В опубликованном [Crypto Pay API](https://help.send.tg/en/articles/10279948-crypto-pay-api) нет P2P-методов. Этот проект работает с интерфейсом пользовательского аккаунта через [MTProto callback API](https://core.telegram.org/method/messages.getBotCallbackAnswer), а не выдуманный P2P REST API.

Использование интерфейса регулируют [правила P2P-сервиса](https://help.send.tg/en/articles/9819590-p2p-market-terms-of-use). Локальные настройки не подтверждают разрешение стороннего сервиса. Устаревший параметр `P2P_AUTOMATION_AUTHORIZED` больше не блокирует подключение; исполнение контролируется `LIVE_TRADING_ENABLED` и отдельным подтверждением владельца в боте. При FloodWait программа сохраняет срок ожидания в базе, выдерживает его и снижает частоту действий.

Для запуска нужны: токен собственного управляющего бота, числовой Telegram user ID владельца, `api_id`/`api_hash` собственного приложения с [my.telegram.org](https://my.telegram.org), пользовательская сессия с доступом к CryptoBot. Вход выполняется локально, коды и пароль 2FA не отправляются управляющему боту.

## Быстрый локальный запуск — Windows

Открой PowerShell **в папке проекта**:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m sniper setup
```

`setup` запросит токен скрытым вводом и ID владельца, создаст `.env` с ключом шифрования и webhook-секретом. Существующий `.env` не перезаписывается. Введи `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` в локальный `.env`, затем:

```powershell
.\.venv\Scripts\python.exe -m sniper auth
```

Телефон, код Telegram и пароль 2FA вводятся в локальной консоли скрыто. Зашифрованная сессия сохраняется в `.secrets/session.enc`. Незашифрованная строка сессии не печатается и не сохраняется.

Команда `auth` проверяет только `APP_KEY`, `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` и настройки файла сессии. При ошибке показывается имя параметра без его значения. Для торговых флагов в `.env` используй `true` или `false`; например, `LIVE_TRADING_ENABLED=false` оставляет реальное исполнение выключенным. Не заменяй существующий `APP_KEY`, если им уже зашифрованы сессия или база.

### Если код входа не приходит

`auth` теперь сообщает способ доставки, выбранный Telegram: служебный чат Telegram, SMS или звонок. Проверь чат Telegram на уже подключённом устройстве, включая архив. Скрипт не умеет принудительно менять способ доставки и не отправляет повторные запросы при неверном вводе кода.

Доступен [официальный вход по QR](https://core.telegram.org/api/qr-login) через уже авторизованное приложение на телефоне:

```powershell
.\.venv\Scripts\python.exe -m sniper auth-qr
```

Перед запуском останови предыдущее ожидание кода через `Ctrl+C`. На телефоне открой Telegram → **Настройки → Устройства → Подключить устройство**. Когда сканер готов, нажми Enter в консоли компьютера. Windows откроет временное PNG с QR-кодом. Отсканируй его внутри Telegram и подтверди подключение. При необходимости введи пароль 2FA в консоли.

QR действует недолго; если истёк, повтори `auth-qr`, предварительно подготовив сканер. Сам QR, его URL, код и пароль никуда не отправляй. QR хранится во временной папке вне проекта; после попытки выполняется очистка. Сессия сохраняется только после подтверждения авторизации Telegram и только зашифрованной. Этот шаг выполняет владелец локально; разработчик не получает код или QR.

Для первого просмотра входящих карточек:

```dotenv
BOT_TRANSPORT=polling
MONITOR_SOURCE=passive
LIVE_TRADING_ENABLED=false
```

Если ранее использовался webhook, переключи доставку на polling; после этого запусти приложение:

```powershell
.\.venv\Scripts\python.exe -m sniper polling
.\.venv\Scripts\python.exe -m sniper serve
```

При быстром перезапуске после аварийного завершения может оставаться блокировка предыдущего процесса. Программа напечатает `waiting_for_worker` и автоматически подождёт до 125 секунд, затем продолжит запуск после освобождения базы. Если другой экземпляр действительно работает, его блокировка не снимается: останови его перед повторным запуском.

В управляющем боте нажми `/start`, задай диапазон и включи уведомления. Для пассивного режима вручную открывай карточки в CryptoBot. `MONITOR_SOURCE=off` позволяет просто пересылать/вставлять карточки в управляющий бот без пользовательской сессии.

### Автоматический мониторинг первой страницы

Для автоматической навигации:

```dotenv
MONITOR_SOURCE=userbot
LIVE_TRADING_ENABLED=false
REFRESH_SECONDS=5
```

Перезапусти программу. Начни с «Уведомления» или «Симуляция». Они проверяют путь по твоему интерфейсу без создания сделки. Курс выставляется **в боте**, исходных значений в коде нет.

Не переключай вручную экраны CryptoBot одновременно с автоматическим поиском: изменения интерфейса могут привести к остановке. `/stop` останавливает новые попытки, но не отменяет уже отправленный запрос.

### Реальное исполнение — только при запуске владельцем

Код реальных операций присутствует. По умолчанию он заблокирован. После самостоятельной проверки интерфейса и разрешения сервиса владелец может установить `LIVE_TRADING_ENABLED=true`, перезапустить процесс и выбрать «Автопокупка».

Бот проверяет активные сделки, затем показывает в той же панели «Подтвердить запуск автопокупки». Рестарт не включает автоторговлю сам. Порог курса повторно читается непосредственно перед отправкой «Создать сделку». Если экран суммы или комиссии не совпадает с распознаваемым форматом, покупка не отправляется.

Если отправка команды состоялась, а ответ потерян, появляется `UNKNOWN`; новая покупка не предпринимается. Проверь «Мои сделки» вручную:

- `/trade D123456` связывает найденную сделку с неопределённой операцией и запрашивает её статус.
- `/resolve` позволяет **после ручной проверки отсутствия активных сделок** сбросить блокировку. Кнопка не отменяет сделку. Отменённое/разрешённое вручную объявление исключается из повторного подбора.
- `/inspect` присылает текущий текст и названия кнопок без callback-данных. Если формат отличается, нужны адаптация парсера и новая проверка.

Кнопка «Отменить сделку» отправляет запрос отмены только после подтверждения владельцем и проверки распознанного ID/статуса. При отмеченной оплате отмена не отправляется. Неизвестный ответ сохраняет паузу. Частые отмены могут ограничивать P2P-доступ по правилам сервиса.

## Бесплатное размещение

### Вариант A — постоянная бесплатная VM, если доступна

Проект рассчитан на обычную Linux VM с Docker. Например, у [Oracle Always Free](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm) есть бесплатные VM в пределах квот. Доступность ресурсов не гарантирована; провайдер может освобождать простаивающие VM. Выбирай только ресурсы с отметкой Always Free и проверяй текущие квоты своего аккаунта.

Перенеси исходники, приватный `.env` и `.secrets/session.enc` на собственную VM. Оставь `BOT_TRANSPORT=polling`, чтобы не требовался публичный HTTPS-вход. Затем:

```bash
docker compose up -d --build
docker compose logs -f --tail=50
```

SQLite находится в постоянном Docker-томе `assistant-data`; HTTP-порт доступен только с самой машины. Храни резервную копию БД вместе с отдельной копией `APP_KEY`; при потере ключа расшифровать настройки нельзя. Не запускай вторую копию приложения с другой БД и той же пользовательской сессией.

### Вариант B — Render Free + внешняя PostgreSQL

Включён `render.yaml` с бесплатным Web Service. Этот вариант **не даёт постоянного мониторинга 24/7**: [Render Free](https://render.com/docs/free) засыпает после 15 минут без входящего трафика. Пока сервис спит, объявления не отслеживаются. Исходящие запросы к Telegram не гарантируют, что сервис останется активным. Искусственных keepalive-запросов в проекте нет.

1. Создай приватный Git-репозиторий из папки проекта. Не загружай `.env`, `.secrets`, `.tgcloud`, БД или файлы сессий.
2. Подготовь внешнюю PostgreSQL. Например, [Neon Free](https://neon.com/docs/introduction/plans) имеет бесплатные квоты. На дату проверки — 100 CU-часов на проект и 1 GB хранения; постоянный мониторинг/heartbeat расходует вычислительную квоту и может её исчерпать. Не обещается бесплатная круглосуточная работа.
3. Создай Render Blueprint из `render.yaml`. В Environment задай `BOT_TOKEN`, `ADMIN_USER_ID`, **тот же** `APP_KEY`, `WEBHOOK_SECRET`, `DATABASE_URL` с TLS. SQLite на Render не используй: файловая система непостоянна.
4. Для пользовательского клиента перенеси `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` и **зашифрованное** содержимое `.secrets/session.enc` в `USER_SESSION_ENCRYPTED`. Выбери нужный `MONITOR_SOURCE`; разрешения и реальное исполнение по умолчанию выключены.
5. После успешного развёртывания запиши полученный HTTPS-адрес в локальный `.env` как `PUBLIC_BASE_URL` и выполни локально `python -m sniper webhook`. Останови локальный процесс, прежде чем запускать ту же сессию в облаке.
6. Отправь `/start` боту. Холодный запуск бесплатного сервиса может задержать ответ. При перезапуске реальная автоторговля остаётся выключенной до нового подтверждения.

Миграции выполняются автоматически перед запуском. Webhook подтверждает получение только после сохранения обновления в БД. Не создавай второй экземпляр с другой БД: блокировка координирует только экземпляры, использующие общую БД.

## Telegram Serverless — необязательный вход для управляющего бота

Можно сохранить выбранный тобой Serverless: каталог `serverless/` содержит обработчики, передающие обновления Python-сервису. Сам Telethon работает на отдельной машине. Это не перенос всего пользовательского клиента в Serverless.

1. Сначала настрой доступный по HTTPS Python-сервис с `BOT_TRANSPORT=webhook`.
2. В `serverless/tgcloud/lib/` скопируй `config.example.js` в `config.js`. Введи адрес сервиса и такой же `WEBHOOK_SECRET`. `config.js` исключён из Git.
3. В BotFather включи Serverless для управляющего бота. CLI-токен Serverless отличается от Bot API-токена.
4. В папке `serverless/` выполни:

```bash
npm install
npx tgcloud login
npx tgcloud push
npx tgcloud webhook sync
```

При использовании мостика **не выполняй** `python -m sniper webhook`: webhook должен оставаться под управлением Telegram Serverless. Все обновления проверяются по владельцу на Python-стороне; повторная доставка дедуплицируется. Если Python-сервис недоступен/спит, мост возвращает ошибку для повторной доставки Telegram. Сам мост без развёрнутого Python-сервиса не выполняет поиск.

## Команды и состояние

| Команда | Назначение |
|---|---|
| `/start`, `/settings` | Меню, режим и курсы |
| `/resume`, `/stop` | Включение и остановка новых попыток |
| `/status` | Источник, счётчики, активная отметка |
| `/history` | Последние 10 карточек |
| `/inspect` | Текущий экран в userbot-режиме |
| `/trade D…` | Привязка ID после неизвестного исхода |
| `/resolve` | Сверка отсутствия сделок самим владельцем |
| `/diagnostics` | Обезличенный отчёт без текстов, токенов и сессий |

Доступ разрешён владельцу `ADMIN_USER_ID` и одобренным им пользователям, только в личных чатах. Профили пользователей разделены, права проверяются при обработке команд и попытках входа. FSM настроек сохраняется в БД. Состояние, очередь Telegram-обновлений и очередь уведомлений зашифрованы Fernet. Шифрование защищает копию БД; работающий процесс имеет доступ к расшифрованным данным. Строки сессии отдельно зашифрованы. Коды/2FA не записываются.

Хранится до 100 карточек, 100 записей аудита, 2000 ключей дедупликации/исключений; обработанные очереди очищаются через 7 дней. Уведомления имеют доставку «как минимум один раз»: при потере ответа Telegram уведомление может повториться. Повтор уведомления не запускает повтор финансовой операции.

Одна реплика, один Uvicorn worker. Межпроцессная аренда в БД не даёт одновременно запустить второй worker с той же БД. Финансовое состояние сохраняется до внешнего запроса. `/healthz` не содержит секретов; `/metrics` и `/api/status` требуют `Authorization: Bearer <WEBHOOK_SECRET>`.

```bash
python -m pip install -e '.[dev]'
python -m pytest -q
python -m ruff check sniper tests migrations
python scripts/benchmark.py
```

Тесты не используют настоящие токены, Telegram-соединения или финансовые операции. Benchmark измеряет только локальный парсер, не задержку обнаружения на рынке. Результаты и непроверенные части — в `VALIDATION.md`.

Для отзыва пользовательской сессии: `python -m sniper revoke` либо раздел устройств в Telegram. Секреты и сессии из архива проекта отсутствуют; их создаёт владелец при настройке.
