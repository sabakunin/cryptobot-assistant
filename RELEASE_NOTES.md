# CryptoBot Assistant 0.3.3

## Восстановление поиска

- До создания сделки временные сбои экрана и тайм-ауты больше не выключают поиск сразу. До трёх попыток восстановления через `/p2p` → USDT/RUB/СБП с задержками 1, 2 и 4 секунды; адаптивная задержка Telegram имеет приоритет.
- События обновления экрана не обходят задержку восстановления. Об успешном восстановлении приходит одно уведомление.
- Сбой подготовки до команды создания освобождает резерв и позволяет заново проверить то же объявление. Включённый поиск сохраняется; остановка пользователем не отменяется.
- FloodWait сохраняет серверный срок ожидания. После возможной отправки Create операция остаётся UNKNOWN и повторно не отправляется.
- Если формат не распознан после ограниченного восстановления, поиск останавливается с `/inspect` и диагностикой. Диагностика содержит место ошибки без текста исключений, токенов и карточек.
- 197 автоматических тестов прошли, в том числе восстановление → однократное создание на имитации Telegram. Реальные финансовые операции для проверки не выполнялись.

## Изменения 0.3.2

## Повторное разрешение доступа

- Исправлены кнопки доступа, когда у владельца выбран торговый аккаунт: управление пользователями больше не привязано к этому аккаунту.
- После случайного отказа свежая кнопка «Разрешить» работает. Старые кнопки возвращают актуальный список, сохраняя защиту от повторного использования старого одобрения после отзыва.
- Поддержаны ранее отправленные кнопки с привязкой к аккаунту; профиль при их нажатии не переключается.
- 181 автоматический тест прошёл, включая сценарий «выбран аккаунт → отклонить → старая кнопка → разрешить заново» и запрет одобрения чужим пользователем.

## Изменения 0.3.1

## Ускорение навигации

- Базовая пауза между нажатиями уменьшена с 2 до 0,2 секунды; `ACTION_INTERVAL` позволяет её настроить.
- Переходы к объявлению, кнопкам «Купить» и «Макс.» используют свежий экран из событий Telegram без лишнего запроса истории.
- Перед созданием и отменой остаётся обязательное чтение актуального экрана. Новое событие не перезаписывается устаревшим ответом истории.
- Новое событие первой страницы сразу будит поиск. Периодическое обновление имеет целевой интервал 1 секунду от начала предыдущего прохода.
- При FloodWait сохраняются срок ожидания и увеличенные интервалы аккаунта. Дополнительное замедление снимается после спокойной минуты; серверный срок ожидания не сокращается.
- В одном живом замере открытие карточки ускорилось с 2,675 до 0,411 секунды. Финансовые кнопки не нажимались; это не замер создания сделки.
- 178 тестов прошли; проверки отмены, изменения цены, потери ответа и повторного создания сохранены.

## Изменения 0.3.0

## Доступ по заявкам

- `/start` незнакомого пользователя создаёт заявку и отвечает «Дождитесь ответа администратора».
- Владелец разрешает или отклоняет доступ кнопкой по ID; раздел `/users` позволяет отозвать разрешение.
- Настройки, аккаунты, меню, уведомления, история и QR/2FA разделены между пользователями.
- Отзыв доступа останавливает поиск, блокирует новые операции и не удаляет сведения об открытых сделках.
- Старые кнопки не восстанавливают отозванное разрешение, повторный `/start` не дублирует заявку.
- Для ПК добавлен необязательный HTTPS-туннель с автоматическим обновлением адреса Mini App.
- Проверка действующего сервиса и границы проверки: [LIVE_ACCESS_CHECK.md](LIVE_ACCESS_CHECK.md).

## Изменения 0.2.2

## Исправление /start

- Команда выводит главное меню внизу чата, поэтому ответ больше не теряется в старой переписке.
- Повторные команды за пять секунд объединяются, а кнопки обновляют последнее меню.
- Устаревшие кнопки показывают подсказку. Пауза доступна и со старого меню.
- Неопределённый результат отправки не вызывает автоматическую отправку копий.
- Проверки: 151 автоматический тест; в действующем боте проверены новая отправка меню и отсутствие повторной отправки того же ответа.

## Исправление 0.2.1

- Исправлена потеря экрана при входящем «Сообщение от … по сделке …».
- Уведомления продавцов исключены из выбора текущего экрана, ожидания ответа на кнопку и обработки статуса сделки.
- При серии уведомлений экран проверяется по сохранённому ID. Настоящие новые ответы CryptoBot и изменения самого экрана по-прежнему проверяются.
- Сообщение продавца с номером старой сделки больше не создаёт ложную паузу. Слова продавца об отмене или оплате не меняют статус сделки.
- 147 автоматических тестов прошли, включая сценарий со скриншота и сообщения до/во время обновления страницы.

## Изменения 0.2.0

Дата: 16 ноября 2026.

- Раздел «Аккаунты» и параллельные пользовательские клиенты; по умолчанию до трёх.
- Независимые курсы, история, дедупликация, пауза, FloodWait и активная сделка на каждом аккаунте.

- Mini App проверяет подпись Telegram и ID владельца. QR и пароль не сохраняются в очередях или журнале; сессии зашифрованы в базе.
- Добавлены `main.py`, `requirements.txt`, включение web-ресурсов в пакет, постоянный каталог для FadeHost и инструкция Northflank/PostgreSQL.
- Старый зашифрованный файл сессии импортируется один раз с сохранением настроек. После удаления аккаунта не импортируется снова.
- При первом выборе автопокупки без курса бот сразу предлагает его ввести.

## Обновление существующей установки

Останови приложение, сохрани базу и исходный `APP_KEY`. Обнови код и зависимости. Существующая сессия импортируется автоматически при первом старте версии 0.2.0. Настрой `PUBLIC_BASE_URL`, если нужен вход внутри Telegram. Старые меню обнови командой `/start`. Автопокупку после перезапуска нужно включить заново для каждого аккаунта.

Нельзя одновременно запускать старую и новую версии с одним Bot API токеном. Новый сервер должен использовать исходные ключи, если переносится существующая база. Для новой установки без переноса базы аккаунты подключаются заново через QR.

## Границы проверки

181 локальный тест прошёл. Проверен запуск распакованного ZIP через `python main.py`, миграции и загрузка ресурсов Mini App с отказом неавторизованным запросам. Проверка не использовала настоящие учётные данные.

Локальные автоматические проверки используют имитацию Telegram для авторизации и финансовых действий. Настоящая навигация CryptoBot была проверена ранее для одного аккаунта до экрана подтверждения; отчёт `LIVE_VERIFICATION.md` относится к этой предыдущей проверке. Новый веб-вход и одновременная работа реальных аккаунтов ещё не проверены на опубликованном хостинге. Создание, отмена, оплата и выпуск криптовалюты при выпуске релиза не выполнялись.
